# results/

Raw Perlmutter outputs and an organized copy of them. **Start with [`MANIFEST.md`](MANIFEST.md)**: one row per run with its job, nodes, world size, seed, GPU model,
metrics and a validity label. Everything in it is computed from the files, not from run names.

## Layout

| path | what |
|---|---|
| `MANIFEST.md` | generated by `tools/organize_results.py`: jobs, runs, evidence for split files, long-run and 2-node comparisons, GPU utilization, hours, superseded snapshots |
| `organized/job<ID>_<N>node_<interactive\|batch>/<run>/` | `config.json`, `metrics.jsonl`, `step_times.csv` and `_provenance.json` (evidence, notes, raw md5s) for each run, plus that job's `gpu_*.csv` and batch `.out` log |
| `organized/_suspect_collision/` | runs whose files could not be attributed (empty when everything is settled) |
| `organized/_unattributed/` | runs with no job from any file (empty when everything is settled) |
| `runs.jsonl`, `runs/`, `gpu/`, `RESULTS.md` | the first-session results added in PR #4 (job 60622124 only); `RESULTS.md` is built by `tools/make_results.py` |
| `../powersgd_results/` | raw scp copies (`results/`, `results_2node/`, `results_batch/`, `logs/`, `logs_batch/`), untouched and git-ignored. `organized/` holds copies of the newest snapshot of each file |

Rebuild after re-copying (newer snapshots are found by file mtime; the newest wins, older ones are listed under "Superseded snapshots"):

```bash
python tools/organize_results.py --raw powersgd_results --out results
```

## Caveats (read before using any number)

- **Single seed per configuration** (seed 1). The only repeats are `rerun_ddp_s1` / `rerun_r4_s1` (vs the sweep) and the two 2-node jobs; MANIFEST shows how close they land.
- **Do not use final val loss as the headline.** DDP overfits (best val loss at step 500 to 750, then rising while train loss keeps falling). The long PowerSGD runs overfit later
  (rank 4: best at step 2500, then rises; rank 2: best at 4500, rises mildly). Use best val loss and its step.
- **Global batch is 512 (world size 8) on 2 nodes vs 256 on 1 node.** The NanoGPT learning rate is **not** scaled with world size: `lr_eff` is 0.001 at both. Only global batch differs,
  so losses are not comparable between 1-node and 2-node runs. (Only ResNet-18, not run here, scales its LR with batch.)
- **Different GPU models:** the 2-node jobs report `A100-SXM4-40GB`; every 1-node run reports `A100-SXM4-80GB`. Step-time differences between 1-node and 2-node are confounded by the GPU model
  and must not be read as the cost of crossing nodes. Compare PowerSGD to DDP **within** a job, where hardware is the same.
- **Run names reused by two jobs:** `gpt_ddp_2node`, `gpt_r2_2node`, `gpt_r4_2node` were written by both 60627319 and 60623329 into the same folders, so each raw `metrics.jsonl` holds two runs.
  `organized/` separates them per job. Each block is attributed by exact match (see MANIFEST, "Doubled files"). `config.json` is identical for both. Raw `step_times.csv` holds whichever job wrote last;
  the other job's file is recovered from an earlier snapshot where one exists, and is not recoverable for `gpt_ddp_2node` of job 60627319.
- The cosine LR schedule depends on the planned step count, so runs with different `max_steps` (1000, 2000, 6000) are different trajectories, not truncations of each other.
- `comm_bytes_per_step` is the logical payload given to `dist.all_reduce` per rank, not wire bytes. `GPU-h` in the run table is training wall-clock x GPUs. Charged hours (see MANIFEST, "Hours") may differ.
- **GPU utilization from the two interactive CSVs (60622124, 60626982) is provisional:** their end of file is not verified. Job 60623330's elapsed time (19:58) comes from `squeue` at COMPLETING until confirmed with `sacct`.
- `config.json` `rank` is a CLI default (2) for DDP runs, not a PowerSGD rank. `lr`/`batch_size` there are `null` (defaults); the values used are in the `start` line of `metrics.jsonl`.

## Not run

ResNet-18/CIFAR-10 with `train_ddp.py`, FP8 (A100 has no native FP8), tensor parallelism, LSTM in `train_ddp.py`. No files exist for any of these.
