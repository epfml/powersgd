## What was run

NanoGPT (6 layers, 6 heads, 384 dim, block 256, ~10.8M params) on Shakespeare-char, fp32, **one seed (1) per configuration**, per-GPU batch 64 (global 256), effective lr 0.001, `start_powerSGD_iter` 10, eval every 250 steps. Run on NERSC Perlmutter, account `m4431_g`, one node (4x A100-SXM4-80GB), in one interactive allocation. PowerSGD uses PyTorch's built-in DDP hook with error feedback and warm start. The DDP baseline goes through the same Python all-reduce hook so communication bytes are counted the same way. See `docs/RUNS.md` for how it was launched.

## Reading the results

- **DDP overfits.** Its val loss is best at step 750 (1.481) and then rises to 2.209 by step 2000 while its train loss keeps falling to 0.52. Shakespeare-char is ~1 MB of text and the model has 10.8M parameters, so this is expected over 2000 steps.
- **The PowerSGD runs had not converged.** Each one's best val loss is at the last eval (step 2000) and still falling, so they never reached the point where DDP started overfitting.
- **Do not read 'final val loss' as PowerSGD beating DDP.** The lower final numbers for the higher ranks are an overfitting artefact: DDP's *best* val loss is lower than every PowerSGD run's *best* val loss at 2000 steps.
- **Higher rank converges faster per step** (best val loss at equal steps improves from rank 1 to 2 to 4).
- **On one NVLink node, compression costs time and saves bytes.** PowerSGD steps are 4–13% slower than DDP while sending 59–156x fewer logical all-reduce bytes. Inside a node the all-reduce is already cheap, so the low-rank compute is overhead. Whether this flips across nodes is what the queued 2-node job tests.

### What we can and cannot claim

- Supported: DDP converges fastest per step; higher rank converges faster per step; PowerSGD cuts logical communication by two orders of magnitude; on one NVLink node it costs a few percent step time.
- **Not supported:** that PowerSGD gives better models than DDP, that PowerSGD is faster end-to-end, or anything about multi-node behaviour (not run yet).
- One seed per config, 2000 steps. Differences of a few percent in step time or small loss gaps could change with another seed.
